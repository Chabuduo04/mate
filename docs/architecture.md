# Mate 项目架构设计文档

## 一、总体架构

Mate 是一个支持 AI 角色扮演语音聊天的平台，采用前后端分离架构，后端基于 Go 语言，前端基于 React + TypeScript。系统通过 RESTful API 实现前后端通信，支持文本与语音的完整交互流程。

```
+-------------------+         +-------------------+         +-------------------+
|    前端 (React)   | <-----> |   后端 (Go/Gin)   | <-----> |   外部AI/云服务    |
+-------------------+         +-------------------+         +-------------------+
        |                           |                               |
        |  HTTP/REST API            |  HTTP/SDK/API                 |
        v                           v                               v
  用户浏览器/移动端         业务逻辑/服务编排                ASR/LLM/TTS/存储
```

## 二、主要模块

### 1. 前端（frontend）
- 技术栈：React 18, TypeScript, Vite, Tailwind CSS
- 主要功能：
  - 角色选择与展示
  - 文本/语音输入与消息展示
  - 音频录制、播放与上传
  - 与后端 API 通信
- 目录结构：
  - `src/components/`：UI组件
  - `src/hooks/`：自定义hooks（如useAudio、useChat）
  - `src/services/`：API请求封装
  - `src/types/`：类型定义
  - `src/utils/`：工具函数

### 2. 后端（back_end）
- 技术栈：Go 1.21+，Gin Web 框架
- 主要功能：
  - 角色管理与配置（roles.json）
  - 聊天消息处理（LLM服务对接）
  - 语音识别（ASR服务对接）
  - 语音合成（TTS服务对接）
  - 文件上传（七牛云KODO）
  - 会话管理
- 目录结构：
  - `cmd/`：主程序入口
  - `handlers/`：HTTP接口处理
  - `models/`：数据结构定义
  - `services/`：业务逻辑与外部服务集成
  - `config/`：配置加载

### 3. 外部服务
- LLM（大语言模型）：用于生成AI回复
- ASR（自动语音识别）：将语音转为文本
- TTS（语音合成）：将文本转为语音
- KODO（七牛云对象存储）：音频文件存储与访问

## 三、核心流程

### 1. 文本聊天流程
1. 前端输入文本消息，调用 `/api/llm` 接口
2. 后端处理消息，调用 LLM 服务生成回复
3. 返回文本回复给前端

### 2. 语音聊天流程
1. 前端录制音频并上传，调用 `/api/upload` 获取音频URL
2. 前端调用 `/api/voice-chat`，传递音频URL和角色信息
3. 后端依次调用：
   - ASR 服务：音频转文本
   - LLM 服务：文本生成回复
   - TTS 服务：回复转语音
4. 后端返回文本和语音URL，前端展示并可播放

## 四、API 设计

- `GET /api/roles`：获取角色列表
- `POST /api/llm`：发送文本消息，返回AI回复
- `POST /api/asr`：语音识别，返回文本
- `POST /api/tts`：语音合成，返回音频URL
- `POST /api/upload`：文件上传，返回文件URL
- `POST /api/voice-chat`：一站式语音聊天（上传→ASR→LLM→TTS）

## 五、部署与运维

- 推荐使用 Docker Compose 一键部署，前后端及依赖服务可容器化运行
- 支持本地开发与生产环境切换
- 环境变量统一管理，敏感信息不写入代码库

## 六、安全与合规

- 前端仅允许受信任域名访问后端API
- 文件上传需校验格式与大小，防止滥用
- 生产环境建议启用HTTPS
- API密钥等敏感信息通过环境变量注入

## 七、扩展性设计

- 角色配置支持热更新（roles.json）
- 服务层可扩展对接更多AI/云服务
- 前端UI组件化，便于功能扩展
